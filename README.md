# 🏦 Banking Data Analysis Using SQL & Power BI

## 📌 Project Overview

This project focuses on analyzing banking data using SQL and Microsoft Power BI to explore transaction activity, account balances, and customer demographics.

SQL is used to query and analyze the available data, while Power BI transforms the results into interactive dashboards. The project demonstrates how data analysis and visualization can help present banking information clearly and support data-driven decision-making.

## 🛠️ Tools & Technologies

* **SQL:** Querying and analyzing structured data.
* **Microsoft Power BI:** Dashboard development and data visualization.
* **Perplexity AI:** Assistance with dataset research and preparation prompts.
* **GitHub:** Version control, project documentation, and portfolio presentation.

## 📊 Power BI Dashboard

The Power BI report contains two pages designed to present transaction activity, account balances, and customer information through visualizations.

### 📄 Page 1: Transaction & Account Analysis

This page provides an overview of transaction activity, account balances, and monthly transaction patterns.

| No. | Visualization                                 | Description                                                                                                 |
| --- | --------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 1   | **Inactive Accounts by Month**                | Displays the number of inactive accounts each month. The dashboard shows five inactive accounts per month.  |
| 2   | **Total Balance by Account Type**             | Compares account balances across Savings and Current accounts.                                              |
| 3   | **Total of Amount by Customer**               | Compares transaction amounts across customers and highlights differences in transaction values.             |
| 4   | **Monthly Transaction Amount by Month**       | Shows monthly transaction amounts to help identify changes in transaction activity over time.               |
| 5   | **Count of Transactions by Transaction Type** | Compares Debit and Credit transactions. The dashboard displays approximately 5K transactions for each type. |

### 📄 Page 2: Customer & Account Insights

This page focuses on customer balances, monthly trends, account distribution, and customer demographics.

| No. | Visualization                        | Description                                                                               |
| --- | ------------------------------------ | ----------------------------------------------------------------------------------------- |
| 1   | **Monthly Transaction Trends**       | Displays monthly transaction amount and balance trends to help compare changes over time. |
| 2   | **Top 5 Customers by Balance**       | Presents customer balances to support comparisons between customers.                      |
| 3   | **Accounts by Account Type**         | Shows the distribution of accounts across Current and Savings account types.              |
| 4   | **Number of Customers by Age Group** | Displays customer counts across age groups, including 26–35, 36–50, and 51+.              |
| 5   | **Customer Count by Gender**         | Presents the customer distribution by gender.                                             |


## 💡 Key Insights

Based on the current dashboard visuals:

* **Transaction Types:** The dashboard displays approximately 5K Debit transactions and 5K Credit transactions.
* **Inactive Accounts:** The inactive-account chart displays five inactive accounts for each month.
* **Monthly Activity:** Transaction amounts vary across months, allowing monthly patterns to be compared.
* **Account Balances:** The dashboard enables comparisons of balances across account types and customers.
* **Customer Demographics:** Customer information is analyzed by age group and gender.
* **Account Distribution:** Current and Savings accounts are presented for comparison.

These observations describe the displayed visuals. Further analysis and validation are needed before drawing broader business conclusions.

## ⚠️ Data Quality Considerations

Some customer amounts and account balances appear negative or unusually large in the dashboard.

These values should be checked against the original dataset, data types, relationships, and calculation logic before being interpreted as meaningful business results.

Validating the data is important to ensure that the dashboard presents accurate and reliable information.
